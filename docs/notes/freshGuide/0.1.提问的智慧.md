# 提问的智慧

大学里没有人有义务回答你的问题。学长学姐、群友、老师、开源社区的开发者，都是从自己的时间里挤出一点来帮你。

同一个问题，问法不同，结果可能是"十分钟后有人给你详细解答"，也可能是"石沉大海"。这篇文章讲的就是这个差别从哪来。

## 一分钟速查

提问前对照一下，这几条做到了，你的问题就已经比大多数人好了：

- 自己先搜过、试过，并在提问时说明搜了什么、试了什么。
- 标题/开场就说清是什么东西出了什么问题，而不是"救命""急""有人在吗"。
- 说清环境：什么系统、什么版本、在哪个页面、什么时候开始的。
- 描述**你看到的现象**，而不是你猜的原因。
- 说清你最终想达成什么目标，而不只是你卡住的那一步。
- 一次问一个地方，别同时私聊十个人。
- 问题解决后回来说一声怎么解决的。

## 提问之前：先自己找一遍

在开口之前，花十分钟做这几件事：

1. 搜索引擎搜一遍报错原文或关键词。
2. 翻一下官方文档、学生手册、教务处/学院通知，或本手册的[常见问题汇总](/notes/freshGuide/FAQ.html)。
3. 在要提问的群里往上翻一翻、用群搜索找一下——同一个问题一天里可能已经被问过三次。
4. 自己动手试一次。很多问题在"试着复现"的过程中就自己解决了。

这不是为了让你少问，而是因为：**你为解决问题付出的努力越明显，别人越愿意接手。** 提问时顺手带上一句"我搜过 XX 和 XX，找到的都是 XXXX，和我的情况不一样"，效果远好过干问一句。

反过来，别指望几秒钟的搜索就能解决一个复杂问题。搜完还是不懂，那才是提问的好时机。

## 怎么问

### 选对地方

- 学院/班级事务问辅导员、班委，不要去技术群问。
- 技术问题去对应的技术群或社区，不要在新生群问 Python 报错。
- 优先在**公开的群或论坛**里问，而不是私聊某个人。公开提问能被更多人看到，也能让后来遇到同样问题的人搜到答案。
- 别把同一个问题同时甩给十个人和五个群。一个一个来。

给素不相识的人发私信是风险最高的方式。别默认"写过教程的人愿意当你的免费顾问"。

### 标题和第一句话就要有信息量

好标题的公式是"**目标 —— 差异**"：先说是什么东西，再说和期望不一样的地方。

> 差：救命啊！我电脑坏了！
>
> 好：ThinkBook 14 接校园网 NJUST-WLAN 时提示"无法连接"，有线网正常

> 差：在吗？有人吗？
>
> 好：想问下大一下学期的体育选课，选不上课的话补选是什么时候开放？

写标题的过程本身就在帮你理清问题：到底是哪一环出了问题？只在这台设备上出现，还是所有设备都这样？一直如此，还是今天才开始？

另外，不要用"在吗""方便问个问题吗"开场然后就不说话了。直接把问题说完整——对方看到时如果能顺手回答，就顺手回答了；等你俩打完招呼，人可能已经忙别的去了。

### 说清楚，但只说相关的

要提供的信息：

- 具体现象，最好带原始报错、截图或录屏。
- 环境：系统和版本、软件版本、校区、哪个网站页面。
- 你已经做过哪些尝试和排查。
- 最近做过什么可能相关的改动。
- 怎么才能重现这个问题。

同时**别把无关内容全倒出来**。几百行日志、十几张截图会让人直接划过去。把能复现问题的最小情况整理出来——精简的过程中你很可能自己就找到答案了。

### 描述现象，而不是你的猜测

如果你的猜测足够准，也就不用问了。所以先把原始现象说出来，让别人自己判断。

> 差：我怀疑是学校防火墙把我 IP 封了，怎么解封？
>
> 好：从昨晚开始，宿舍有线网打不开教务系统（一直转圈最后超时），手机连校园 Wi-Fi 能正常打开，同宿舍其他人有线网也打不开。其他网站都正常。

如果你确实有猜测，说明"这只是我的猜测"，并说清你为什么这么想。

### 说目标，而不只是卡住的那一步

很多人心里有个更大的目标，在自以为可行的路上卡住了，然后只问那条路怎么走——却没意识到这条路本身就走错了。

> 差：怎么用 Word 手动画一个三线表？
>
> 好：我要按学院模板排毕业论文里的三线表，现在只会一格一格设边框，太慢了，有没有更合适的做法？

第二种问法，你可能会得到"换个工具/换个思路"这种真正帮到你的回答。

### 语气与格式

- 把字打通顺，标点正常，别通篇不换行、也别整段全是缩写和火星文。写得潦草，别人会认为你想得也潦草。
- 别刷屏，别连发十几条一句话消息。
- 客气有用，但不能代替把问题说清楚。"请"和"谢谢"值得说，"我知道我很菜我是废物但是……"这种就免了——它没有提供任何信息，只让人不适。
- 标题里不要写"紧急"。这是你的时间压力，不是别人的。

### 别急着说"这是 bug"

在你非常有根据之前，先假设是自己哪里做错了。绝大多数时候确实如此。真是 bug 的话，回复里自然会有人告诉你。这条同样适用于本手册：如果你发现内容有误，欢迎[直接提出修改](https://github.com/NJUST-OpenLib/NJUST-Manual)，比只说"你们写错了"有用得多。

## 拿到回答之后

**被回一句"自己去看文档""自己去搜一下"，别不高兴。** 对方的意思是：这个信息很容易找到，而你自己找一遍会学到更多。他愿意打这几个字，说明他并没有无视你。（在技术社区里，这两句常被缩写成 RTFM 和 STFW，见到了不必觉得是在骂你。）

**看不懂回答，先自己查一遍再追问。** 追问时体现出你已经查过：

> 差：xxx 是什么？
>
> 好：我查了文档，只在 -z 和 -p 两个参数里看到 xxx，但没写怎么清除，你指的是哪一个？

**语气直接不等于人不好。** 技术社区习惯直接指出问题，重点在解决问题而不是让人舒服。真被冒犯了也先平静回应；如果对方确实过分，围观的人一般会出面。为了一句话开战，最后受损的是你获得帮助的机会。

**没人回答，不代表被无视。** 可能只是看到的人恰好不知道答案，或者你的问题一开始就没组织好。别原地反复刷同一个问题，隔一段时间换个说法、补充更多信息再问，或者换个更合适的地方问。

## 问题解决后，回来说一声

这一条最容易被忽略，但很重要。

解决之后，回到原来的提问处补一句：**问题是什么原因，怎么解决的，谢谢帮忙的人。** 一句"找到了，是网线松了，谢谢大家"就够了，不必长篇复述过程。

这么做的好处：帮过你的人能得到闭环；后来搜到这个帖子的人能直接看到答案；也会让人愿意在下一次继续帮你。

## 如果你成了回答者

新生很快就会变成学长学姐。到那时候：

- 态度和善一点。被问题困住的人容易显得急躁或笨拙，其实不是。
- 不确定就明说。一个听起来很权威的错误答案，比没有答案更糟。
- 别开会毁掉别人环境的玩笑，总会有人当成真的指令去执行。
- 反问以引出细节，试着把一个蠢问题变成好问题。我们都当过新手。
- 觉得对方该自己查，也尽量给个链接或搜索关键词，而不是只丢一句"自己看文档"。
- 如果同一个问题反复被问，想想是不是该写进文档或 FAQ 里——[这本手册欢迎你来补充](https://github.com/NJUST-OpenLib/NJUST-Manual)。

::: warning 最后一点提醒
学会提问，同时也要学会**核实**。群里有人发"最新通知，请加入官方新生群 xxxx""交资料费 138 元，逾期无法报考"，正确做法不是在群里 @ 发布者问"是真的吗"，而是去官方渠道核实。详见[防骗指南](/notes/freshGuide/antiScam.html)。
